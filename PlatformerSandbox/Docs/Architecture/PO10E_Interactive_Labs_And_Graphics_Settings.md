# PO10E UI and graphics settings candidate

## Integration and scope
Overlay on the locally verified PO10D candidate, including the prior PO10A–D changes. Extract into the existing solution root. Full replacement files, no generated binaries. This batch deliberately does not modify shader algorithms. The prior source export still lacks all .fx, .mgcb and .csproj files. Camera-independent GPU mask textures, regional texture pooling, fused material passes, alternate formats and general static shadow-casting fields remain blocked. The existing world-space geometry cache and camera convergence optimization are retained.

## Permanent UI rule
Every user-operable option must have a visible control with a name and current value. Show selectable alternatives explicitly. Shortcuts may supplement but never replace the controls. Display disabled controls and their reason. Use shared hit/draw layout, mouse and keyboard/controller navigation, explicit focus/return to gameplay, and a collapsible panel. No UI input should leak into gameplay movement or jump. Keep saved application settings separate from temporary lab overrides and automated test configurations. Apply this rule to all new game menus/labs. Legacy labs and non-lighting gyms are not migrated in this batch.

## Lighting Quality Lab and Engine Performance Lab
- Both use a new reusable, right-aligned paged control panel with visible toggles, direct choice lists, action buttons, status rows, and a shared headless draw/hit geometry. Previous and Next buttons expose additional rows. Click the title to collapse/expand. Click the center footer (PLAY) or outside the panel to return to gameplay. Tab / controller RB is an optional focus shortcut; Up/Down selects, Left/Right changes page, Enter/A activates, Esc/B releases focus. A choice list has its own Back row. The player receives neutral input during focus. A held jump is reseeded on return, not converted into a fresh press.
- Profiles, fixture, workload, lighting, freeze, wall motion, hard/soft edges, bloom, emission, production normal-map capture, camera sweep, hull overlay, VSync, FPS limit, quality, light/shadow/bloom scales, area samples, ambient multiplier, static fields, all seven original flags and five PO10A flags, and live metrics. The PO10A profile is intentionally independent of the original seven-flag mask; reference comparison in Quality Lab starts with mask 127. Quality Lab uses optimized full as its default. The manual Performance Lab starts with the reference PO10A profile and original mask zero, preserving the older performance lab baseline. Process-lifetime switches (including PO04B flags) are read-only, run via environment or the benchmark tool.
- Normal-map switch disables production material normal capture (neutral normal fallback), not every other orientation/rim effect. Ambient is a multiplier on authored RGB ambient, not a change to authored material data. Light/scene animation uses the existing freeze behavior. Existing DEV TOOLS remains available for other scene-specific settings.
- Manual Performance Lab supports single capture with Quick (60/120), Standard (90/180), Full (120/300), and custom frame lengths. Original Quick/Repeated Sweep are explicitly labeled legacy mask sweeps; they retain existing case lists and lengths. Python still runs the full automated tiers. Capture collapses the panel and releases focus; a visible Cancel button remains. Expanding the panel cancels an active capture to avoid mixed UI workloads. Manual captures include the compact panel overhead and are not identical to automated cases.
- Controls refresh at 8 Hz while expanded, plus immediate input updates. Collapsed captures avoid rebuilding controls each frame. The automated runner keeps the existing rendering/hud and does not use the new manual panels. It is still the authoritative performance comparison.

## Graphics Settings
Main menu or Pause > Settings > Graphics Settings. Options include 720p/900p/1080p, windowed/fullscreen, VSync, FPS limit, rendering profile, lighting quality budget, independent lighting/shadow/bloom scales, area sample policy. Select a value from the visible choices; Apply and Save commits; Back discards pending edits; Reset Draft Defaults does not apply until confirmed. Profiles are explicit opt-in for production optimizations; the default reference preserves prior production mask zero. Individual overrides keep the selected base profile, with a Custom label. All saved settings are validated before applying. Resolution choices above the current primary display are rejected. Display apply failures roll back to prior graphics device settings when possible; automatic timed fullscreen rollback is not implemented. If an unsupported display configuration causes a startup issue, remove `%LOCALAPPDATA%\PlatformerSandbox\Settings\graphics.json` and relaunch.

The file is written via a temporary file followed by replacement. Invalid/missing JSON uses previous process defaults. No graphics preferences are saved implicitly when a lab changes. Lab-local state is restored on scene exit. Saved display settings apply globally when explicitly saved; lab-specific lighting/pacing overrides remain independent. Explicit PS_PO_* environment variables disable saved preferences for that process and make the graphics settings read-only. Automated runs always use their supplied process configuration. If running ordinary game with persistent settings, launch in a fresh PowerShell without PS_PO_* overrides. This is a conservative policy so benchmark results are reproducible.

## Acceptance procedure
1. Run `dotnet test .\PlatformerSandbox.Tests\PlatformerSandbox.Tests.csproj -c Release`.
2. Build `dotnet build .\Platforms\DesktopGL\PlatformerSandbox.DesktopGL.csproj -c Release`.
3. Launch normally. Select Lighting Quality Lab. Verify choices, toggles, current state, collapse/expand, every page, mouse/controller/keyboard navigation. Verify movement, jumping, and camera sweep with UI unfocused; while focused D-pad/arrow/confirm must not move or jump. Click outside/PLAY and resume. Check 100%, 75%, 50%, 25% and experimental profiles, normals, bloom, soft shadows and all fixtures. Check that no UI controls overlap other HUDs at 720p and 1080p.
4. Select Engine Performance Lab. Choose Quick single capture, start, observe status and cancel; repeat and allow completion. Verify saved CSV status. Try custom lengths. Do not confuse legacy in-game sweeps with the Python suites.
5. Open Settings > Graphics Settings from title and pause. Try a draft change and Back (no save), then Apply and Save. Restart game, verify values persist. Confirm changes made in lab do not change the saved values. Verify normal gameplay in Connected Cavern and return to menu. Test invalid JSON fallback only after backing up the file.
6. For performance smoke: `py .\Tools\po_run_benchmarks.py --po10d --tier quick --no-build` (5 cases, if the Release build above succeeded). Automated output should still use process-defined dimensions and flags regardless of saved preferences. For pixel parity: `py .\Tools\po_visual_regression.py --temporal --no-build`. No full 78-case benchmark needed.

## Validation and limitations
All 16 pre-existing Python benchmark/visual infrastructure tests passed; PO10D quick plan generated. Added C# tests for row hit/layout paging, collapsed behavior, graphics preferences roundtrip/invalid JSON, profile overrides, and menu stack. C# build, unit execution, live input, rendering and persistence on Windows remain unverified; this environment has no dotnet and the source export lacks project configuration. New source files are placed in existing project folders following prior candidate patterns; actual compile inclusion must be confirmed by local build. No new rendering speedup is claimed. The UI is a pragmatic paged button/choice implementation, not a full generic GUI toolkit: freeform sliders, tooltip framework, comprehensive remapping, and migration of every legacy gym are future work. Production preset and fullscreen device behavior require manual acceptance. Remaining shader work requires a complete source archive: `py .\Tools\po_export_source.py`; review before uploading.
