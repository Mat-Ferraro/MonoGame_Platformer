# PB01D–F — Translational rigid body candidate

Baseline: user-validated PB01A–C (2,011 unique C# test cases in each spatial mode). This is an additive source overlay, not a replacement engine. Status: candidate, C# build and runtime acceptance pending.

## Scope and motion authority

The existing kinematic character motor, jump trajectories, ability/state system, and platform trajectories remain unchanged. DynamicBodyWorld owns dynamic AABB translational state; WorldSession calls it once at the same fixed tick boundary as the existing staged character updates. All dynamic body results are staged before commit. No character mass is assigned. The integrator uses semi-implicit Euler acceleration and swept linear segments during each tick. It is not an analytical continuous-acceleration solver. The existing PO05 terrain sweep and Reference/Indexed/Verify modes are reused. Terrain overlap at creation or re-enabling contact is rejected; contacts snap to the exact contacting face; an exhausted bounded contact budget reports a genuine failure, not a swallowed exception.

Forces and impulses are accumulated and consumed at the next successful tick; continuous force must be requested on each tick. Gravity scale, explicit or density-derived mass, exponential linear damping, velocity component caps, static/dynamic friction, restitution, and low-speed bounce threshold are configurable. Friction is based on normal collision impulse, not a general resting contact force solver. All terrain uses Default physics material unless a terrain material dictionary is passed to DynamicBodyWorld. Rotational dynamics remain PB02.

The collision filter contract provides symmetric category/mask tests, and individual dynamic-to-terrain exclusions. Restoring an overlapping pair or mask is rejected until valid. Removing an object clears its exclusions. Unsupported dynamic/dynamic, character/dynamic and moving-platform/dynamic masks are explicitly rejected rather than simulating an inaccurate response. These interactions, carrying, stacking, transitive pushes, coupled chronological resolution, multi-body crush detection and selectable crush policies require PB01G–L. The previous named-spawn crush recovery remains unchanged. Diagnostic exceptions and numerical fault policies are not replaced. Physics props can pass through characters, other props and moving platforms in this phase; they are not yet gameplay-pushable by walking into them.

## Authoring and presentation

`Content/Physics/DynamicBodies.json` is a versioned sidecar keyed by level identifier; centers and half extents are Y-up world units. It is loaded during LDtk scene preparation, before scene activation. Existing levels with no entries receive no dynamic integrator. Five fixtures in Physics Interaction Lab and eight in Engine Integration Lab exercise falling, bounce, sliding and zero-gravity. Terrain materials remain Default in those fixtures. LDtk entity schema authoring follows PB01N. Dynamic objects appear in the gameplay receiver layer with graybox visuals. They receive layer lighting but do not yet contribute shadow occluders or production material maps. Existing animation, particles, audio, lighting, scene flow and wind continue independently. The integrated lab is still not a complete showcase of all advanced engine systems.

Visible physics panel: body selection, spawn above player, remove, fixture reset, JSON material reload, material/mass/gravity choices, mask enable, terrain collider selection/pair exclusion, impulses left/right/up, one-tick force, state and timing readouts. The Integration Lab has a physics page accessible from its lighting panel. Reset fixtures after deliberately disabling terrain collision; free-falling bodies may leave level bounds. There is no automatic despawn or general entity lifecycle yet. No new hidden key shortcuts.

## Automated validation

Clean/rebuild solution. Run `dotnet test .\PlatformerSandbox.Tests\PlatformerSandbox.Tests.csproj -c Release --filter "FullyQualifiedName~PB01DynamicBodyTests|FullyQualifiedName~PB01FoundationTests"`, then `py .\Tools\pb01_validate.py --tier quick`. Full suite repeats C# tests under Reference, Indexed and Verify and produces old fixed-tick legacy reports plus new dynamic tick reports for both levels. New tests check mass-dependent motion, gravity, damping, restitution/friction, swept thin-wall collision, filter restoration, invalid spawn/reload, stable order, transactional failure, snapshot registration, and actual dynamic replay versus legacy kinematic replay.

Visual tests capture both labs; Quick 60 ticks/target body 1 (6 captures); Full 30/60/150 ticks with targets 1/2/4 (18 captures). Capture metadata must prove target visible, contacts at >=60 ticks, and matching body signatures/positions, camera, player and light state. Repeated reference and indexed must match pixels. Visuals do not prove untested shared contacts.

Integrated benchmark: Quick 60 warmup simulation ticks + at least 300 measured ticks; Standard 300 + 900; Full 300 + 1800. Captures run in variable rendering mode with the existing fixed-step simulation. Capture endpoints sampled at render intervals may overshoot by up to 15 measured ticks; recorded actual tick span is required. Frame counts are variable. Impulse to body 1 every 60 world ticks keeps motion active. Output includes dynamic body count, sweeps, contacts, cumulative integrator CPU time and per-tick mean, prior renderer/frame/GC/lighting/audio counters. Graphical workload is rejected if bodies, sweeps or contacts are missing. Not a pixel-exact benchmark replay; fixed-tick C# and visual tests supply deterministic evidence. Previous 120-frame PB01A–C results are not directly comparable to these new duration-based workloads.

Manual acceptance: both levels load; character movement matches prior feel; wood falls and settles; rubber bounces; ice slides; zero gravity fixture stays suspended; mass and material edits affect subsequent impulse; reset/reload works; pair exclusion affects only chosen prop; invalid re-enable is rejected; props can be removed/reset; scene transitions clear old body state; integrated rendering and audio remain functional; prior crush regression remains fixed. Test expected unsupported prop interactions as pass-through, not as working pushes.
