# PB01A–C — Physical body foundation candidate

## Contract and scope

- Existing `CharacterMovementController` remains authoritative. Characters are kinematic and not dynamic rigid bodies; existing authored trajectories remain authoritative for moving platforms.
- `PhysicalBodyId` is a world-scoped kind/local-ID pair. This is an adapter identity for existing collider, platform and character ID spaces, not a replacement for the future entity registry. Stable over the lifetime of an existing body; generation/reuse policy belongs to entity lifecycle.
- `PhysicalBodyDefinition` is immutable, has axis-aligned extents, a material ID and optional dynamic-only mass override. `PhysicalBodyFrame` is a detached, validated, sorted committed observation. It cannot move a body or be fed back as a command.
- `WorldPhysicalBodyView.Capture` adapts `WorldSession` static colliders, analytical platform samples and committed player snapshots (using CharacterId, not PlayerId or input source). No controller or collision algorithms changed by PB01A–C. Capture is explicit/on demand, not a new per-tick production cost.
- `Content/Physics/Materials.json` defines seven initial, editable gameplay materials. The catalog enforces valid finite values, unique names, required Default, schema version and explicit enum rules. Friction uses geometric mean and restitution uses maximum by default. Separate rules can be authored. Density is mass per square world unit, not SI density; no mass for kinematic/static bodies. Physics materials do not change character movement profiles or visual materials. Material preview is not a contact solver.
- Body transforms and contacts remain AABB-based in this pass. Future PB02 adds orientation, angular velocity, inertia, torque, rotated shapes and angular contacts; no inactive rotation controls pretending to work.

## Two-level contract (standing requirement)

1. **Physics Interaction Lab**: new standalone level, 3072 x 1024, flat floor, side pusher, overhead crusher and a carrier, with visible spatial controls, read-only body counts and editable JSON material pair preview. Press the visible reload control after editing JSON. No dynamic props yet. The legacy LDtk field names `VelocityX/Y` are passed to `MovingPlatformTrajectory` as total offsets, not velocities; authored test travel uses that existing contract. Existing crush fix is bundled so the current intended behavior is respawn at a safe named spawn; intentional diagnostic throw and no-safe-spawn behavior are still as documented in PO05_Crush_Recovery.md. Do not treat this temporary policy as universal resolution.
2. **Engine Integration Lab**: new standalone authored cavern variant with its existing terrain art, foreground/background, parallax, animated character, moving platform, wind, checkpoint, particle zones and world lighting. Source is the existing CAVERN_A fixture. Exits removed to keep capture in one scene; transition behavior remains in Connected Cavern. It uses the existing visible quality-lab controls and standard compatibility renderer. Do not infer coverage of every existing feature from its level name. It is an evolving integration baseline, not yet an all-capability showcase. Add every compatible new feature in both levels when its real runtime is implemented, with a coverage ledger; use explicit configurations for mutually exclusive policies.
3. **Automation**: same three spatial modes; fixed tick replay compares player state, events, platforms and observer; measure fixed-tick CPU/allocations separately from rendering. Feature lab fixed-tick pixel repeat and spatial A/B. Integration lab uses the existing frame-based benchmark with scripted input, actual scene IDs/spatial execution evidence, native adapter and AC guard. Capture frame mean/P50/P95/P99/max, CPU work by subsystem, allocations and GC, lights and particle counts, actual between-recorded-frame simulation tick delta. Frame-count measurements are NOT fixed simulated-time workloads; compare fixed-tick tests for simulation costs, report differing tick/particle workloads when interpreting graphical numbers. Integrated exact pixel regression requires a separate determinism assessment for animated/particle presentation.

## Deliverable boundaries

PB01A–C candidate only. No runtime dynamic body integrator, contact graph, push/stack solver, force/impulse integration, material-driven friction/bounce, pair filtering, platform pause/reverse, universal multi-body crush or death/destruction lifecycle. These remain PB01D–P. Existing PO05 crush recovery files are included unchanged except Game1.cs (also extends scene activation and benchmark metadata), because application of that patch was not confirmed. Baseline assumes PO05 candidate, compile fix, visual fix and GPU refinement already installed. No C# execution available in authoring container; validate locally. No optimization flag is promoted to production. Experimental GPU options disabled in automated baseline.

## Implementation sequence

- PB01D/E: actual force-driven translational dynamic bodies; integrate into shared authoritative world, not a second independent solver. Gravity, impulses, friction, restitution. Keep legacy kinematic motion.
- PB01F/G: collision layers/masks, pair exclusions, runtime platform trajectory clock and control.
- PB01H/I: contact graph, multi-body pushing, stacking and carrying, continuous collision/event scheduler integration.
- PB01J–M: generalized compression, deterministic mixed policies, death/destruction and safe respawn, spatial registration and atomic commit. No special-case handling per level. Preserve blocked-spawn wait policy as target, not current functionality.
- PB01N–P: LDtk entity/material authoring, live scenario controls, integrated level expansion, automated suite and acceptance. Expand tests during each preceding phase, not just at the end.
