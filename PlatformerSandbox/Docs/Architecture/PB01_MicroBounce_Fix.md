# PB01 micro-bounce stability fix

Applies over PB01F-P Consolidated Partial Candidate. No character motor, platform trajectory, geometry, or material coefficient changes.

A body resting against solid terrain can acquire inward velocity from gravity/force at every fixed tick. The original restitution cutoff only compared the impact to a fixed authored speed, allowing sustained bouncing when the per-tick acceleration exceeds that cutoff. The terrain solver now suppresses restitution for inward normal impact speeds at or below max(authored BounceThreshold, sustained inward acceleration increment). Pending impulses are excluded from the acceleration increment. Restitution also discounts the unelapsed portion of sustained inward acceleration at the first contact on each axis, avoiding artificial rebound energy from the full-tick velocity approximation. The cutoff compares this estimated impact speed with the maximum above. Contact snapping and the tangential friction formula remain unchanged (the normal impulse reflects the actual rebound). This is a targeted stabilization of the existing linear sweep, not a fully time-of-impact accelerated integrator. This does not implement sleeping or the pending coupled contact solver. A real outward impulse can move a resting body again.

`BounceThreshold` is already supported per fixture in Content/Physics/DynamicBodies.json, in world units/s (default 0.5). The developer physics panel now exposes the authored threshold for the selected body. The automatic acceleration floor remains active even at a configured threshold of zero. Changes in the panel are runtime-only; edit the fixture JSON for persistent per-body tuning. No existing JSON files need changing.

New xUnit cases cover resting gravity in three spatial modes and multiple tick rates/gravity scales, bouncing then settling using the authored rubber material, sustained wall force, tangential sliding, inclusive cutoff, and renewed motion after an impulse. Run `dotnet test .\PlatformerSandbox.Tests\PlatformerSandbox.Tests.csproj -c Release --filter "FullyQualifiedName~PB01DynamicBodyTests"` and `py .\Tools\pb01_validate.py --tier quick`. The .NET SDK is not available in the packaging environment; C# execution remains local validation. A scalar Python model of the floor integration can verify the intended cutoff behavior but is not a substitute for C# tests.
